## 1. 먼저: 확정 규칙과 다르게 구현된 것

- [x] **1-1. 제보자에게 포인트를 주지 않기 (확정)**
  의뢰(제보)를 올린 사람은 포인트가 없고, 해결한 사람만 받습니다.
  현재: `on_heart_added` 가 승격 순간과 이후 하트마다 제보자에게 `report_promoted`/`report_heart` 로 적립합니다.
  완료 조건: 제보자 적립이 없어지고, 해결자 보상(하트 수 × 값, 상한)은 그대로 유지. `docs/api.md` "확정 규칙"의 해당 줄 수정.

- [x] **1-2. 하트를 누른 사람에게 소량 포인트 (확정, 값은 임시 1점)**
  같은 제보에는 한 번만 지급합니다.
  완료 조건: 하트 insert 시 누른 사람에게 적립, `point_ledger.reason` 에 구분값 추가.

- [x] **1-3. 하트 취소 없음 (확정)**
  눌렀다 떼기로 포인트·승격을 조작하지 못하게 합니다. 앱은 누른 뒤 4초 동안만 되돌리기를 받고, 그 시간이 지난 뒤에 insert 를 보냅니다(PR #10).
  현재: `report_hearts` 에 delete 권한과 `own heart delete` 정책, `on_heart_removed` 트리거가 있습니다.
  완료 조건: 클라이언트가 delete 할 수 없음. `docs/api.md` 하트 예시에서 취소 코드 삭제.

- [x] **1-4. 하트 하루 10개 상한 (확정)**
  한국 시간 0시 기준. 의뢰 완료 하루 3개 상한과 별개로 셉니다.
  완료 조건: 11번째 insert 는 `HEART_DAILY_LIMIT` 에러. `my_profile` 에 오늘 쓴 하트 수와 상한(`hearts_today`, `hearts_limit`), 오늘 완료 수와 상한(`completes_today`, `completes_limit`)을 함께 반환.

- [x] **1-5. 포인트와 XP 분리 (확정, 수치는 임시)**
  포인트는 상점에서 쓰면 줄어드는 값, XP는 쌓이기만 하는 값이고 레벨은 XP로 정합니다. 화면에서 둘을 다른 아이콘으로 따로 보여 줍니다.
  현재: 레벨이 누적 포인트(`total_earned`) 200점마다 1레벨이고 XP가 없습니다.
  임시값(프론트가 지금 쓰는 값): 장소 유형별 XP 빗물받이 100 · 버스정류장 80 · 공원 150 · 골목·거리 80 · 기타 50, 개인 레벨 300XP마다.
  완료 조건: `profiles` 에 XP, `approve_claim` 반환에 `xp_gained`, `my_profile` 에 `xp`·`level`·`xp_in_level`·`xp_for_next_level`.

- [x] **1-6. 크루 의뢰 보상 = 포인트 + 크루 활동 경험치 (확정)**
  현재: 크루 의뢰는 개인 포인트 없이 크루 점수 100점만 줍니다.
  완료 조건: 크루 의뢰를 완료하면 개인 포인트와 크루 XP를 둘 다 지급. 크루원이 일반 의뢰를 완료해도 크루 XP가 쌓이고, 크루 의뢰는 2배(임시). 크루 레벨은 500XP마다(임시).
  > 처리(백엔드): 크루 의뢰(`kind='crew'`)는 포인트 값이 요청에 없어 `app_settings.crew_quest_points = 50`(임시)으로 두었습니다. 필요 인원 2명 이상인 주민 제보도 크루 XP 2배입니다.

- [x] **2-15. 해결 확인 알림 (확정, 2026-11-14)**
  의뢰가 해결되면 제보한 사람과 하트를 누른 사람에게 알림을 보내고, 치우기 전·뒤 사진을 보여 줍니다. 받은 사람은 "치워졌어요" 또는 "아직이에요"로 답합니다. 필요한 것: 알림 테이블(받는 사람, 제보 id, 답, 시각), 해결 시 자동 생성, 답 저장 함수, "아직이에요" 수 집계. 해결한 본인에게는 보내지 않습니다. "아직이에요"가 일정 수(임시 2건) 모이면 운영진 검토 대상으로 올리고, 포인트 회수 여부는 3-6 의 보류 지급과 함께 정합니다. 푸시 알림은 앱 빌드 뒤에 붙이고 지금은 앱 안 목록만 있으면 됩니다.

- 주민 제보·크루 의뢰: 의뢰를 올린 사람 50% + 하트 누른 사람(크루 의뢰는 다른 크루원) 50% 를 나눠 투표, 60% 이상이면 승인. 올린 사람이 "아직이에요"면 반려. 48시간 안에 결론이 없으면 운영진 검토.
- 제휴 의뢰: 업체 담당자(현장 파견 1명 이상)가 업체 웹에서 승인/반려(`partner_claims`, `partner_review_claim`).
- 하루 3개 상한은 제출 시점 기준.
- 프론트 요청: 인증 완료 화면을 "확인 대기"로, `my_claims` 의 상태 표시, 해결 확인 알림 화면을 투표로(가중치 표시는 선택), 업체 웹에 "인증 확인" 목록과 승인/반려 버튼. 자세한 건 `docs/api.md` "인증 확인".
